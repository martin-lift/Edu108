# JSON на мисия — схема 4

[Начало](../README.md) · [Шаблон](mission-template-json.md) · [Правила](rules.md)

Мисията е самостоятелно описание на конкретните стъпки, които ученикът получава. Съдържанието и правилата са отделени както за цялата мисия, така и за всяка стъпка.

## Минимален пример

```json
{
  "mission_version": 4,
  "mission_id": "hardware-one-question",
  "mission_content": {
    "title": "Хардуер",
    "steps": [
      {
        "id": "step-1",
        "step_content": {
          "type": "open_answer",
          "title": "Определение",
          "instruction": "Какво е хардуер?"
        },
        "step_rules": {}
      }
    ]
  },
  "mission_rules": {}
}
```

Празните обекти за правила са валидни и означават подразбиращите се стойности. Самите обекти `mission_content`, `mission_rules`, `step_content` и `step_rules` са задължителни.

## Основен обект

| Поле | Тип | Значение |
|---|---|---|
| `mission_version` | integer | Задължително `4`. Версия на JSON формата. |
| `mission_id` | string | Задължителен непразен идентификатор на конкретната мисия. |
| `mission_content` | object | Задължително съдържание на мисията. |
| `mission_rules` | object | Задължителни правила на мисията; може да е `{}`. |
| `student` | object | Незадължителни служебни данни, които Teacher108 добавя при получаване на мисия след вход. Не са част от авторските примери. |

**Мисията е непроменяема след генериране и няма `revision`.** Редактира се шаблонът и се генерира нова мисия с ново `mission_id`. Teacher108 отказва да презапише вече съхранена мисия със същото ID и различно описание. `mission_version` обозначава версията на JSON структурата, а не на учебното съдържание. `step_content_id` сочи избраното библиотечно съдържание. За шаблоните отделната версия на формата е `template_version`.

Различни мисии, съставени от един шаблон, получават различни `mission_id`. Повторна работа на ученик по една и съща мисия създава нов резултат от мисия, без да изисква ново `mission_id`.

## `mission_content`

| Поле | Тип | Значение |
|---|---|---|
| `title` | string | Задължително непразно заглавие. |
| `steps` | array | Задължителна последователност от 1 до 1000 стъпки. |
| `description` | string | Незадължително описание и цел; запазва се като метаданни, не е отделна начална страница в Student108. |
| `class_name`, `subject`, `category`, `lesson` | string | Незадължителни описателни полета. Могат да липсват или да са празни. |
| `persistent_text` | string | Незадължителен общ текст, показван над стъпките. |
| `content_format` | string | `"text"` по подразбиране или `"html"` за съдържанието на стъпките. |
| `mission_type` | string | `"millionaire"` включва „Стани богат“. При стандартните примери полето липсва. Виж [Типове мисии](mission-types.md). |

Описателните полета за клас, предмет и урок се пазят, но сами не филтрират ученици и не раздават мисията.

## Една конкретна стъпка

```json
{
  "id": "step-1",
  "step_content_id": 101,
  "step_content": {
    "type": "open_answer",
    "title": "Определение за хардуер",
    "instruction": "Какво е хардуер? Дай един пример.",
    "instruction_format": "text"
  },
  "step_rules": {
    "time_limit_seconds": 30,
    "allow_ai_hint": false
  }
}
```

| Поле | Тип | Значение |
|---|---|---|
| `id` | string | Задължително непразно ID, уникално в тази мисия. Свързва стъпката с ученическия отговор. |
| `step_content_id` | positive integer | Незадължително ID на избраното съдържание в учителската библиотека. |
| `step_content` | object | Задължително пълно копие на съдържанието. |
| `step_rules` | object | Задължителни окончателни правила за тази стъпка; може да е `{}`. |

`step_content_id` не замества съдържанието. Student108 трябва да може да работи само с получената мисия. Едно и също библиотечно съдържание може да присъства в различни мисии или стъпки; `id` на всяка стъпка в една мисия остава уникално.

## `step_content`

Общи задължителни полета: непразни `type`, `title`, `instruction`. Незадължително `instruction_format` заменя общия `content_format` за конкретната стъпка.

При избор на отговор се използва `options`, списък от обекти с непразни `id` и `text`. ID на отговорите са уникални в съответната стъпка. `correct_option_ids` винаги е **списък**, включително при един верен отговор. В готова стандартна мисия може да липсва; библиотеката на Wizard 1 изисква да се зададат верните отговори.

`lifeline_data` съдържа данни за жокерите, специфични за тази стъпка. Типовете и примери са описани в [Типове стъпки](step-types.md); жокерите — в [Правила](rules.md).

При HTML Student108 използва разрешен набор от тагове и атрибути. Импортираните скриптове не се изпълняват. HTML е начин за представяне на съдържание, а не начин за добавяне на програмна логика.

## Обратна връзка за свободен отговор

Поддържа се от **Student108 0.14.14** и **Teacher108 0.13.8**. Версиите на форматите остават мисия **4** и шаблон **1**. JSON се записва в **UTF-8**; имената на полетата и идентификаторите са на английски, а текстовете за ученика могат да са на български.

Двата режима са независими булеви параметри в `step_rules`:

| `automatic_feedback` | `ai_feedback` | Поведение при `open_answer` |
|---|---|---|
| `false` или липсва | `false` или липсва | Свободен отговор без обратна връзка. |
| `true` | `false` или липсва | След предаване показва предварително зададения `step_content.reference_answer`. |
| `false` или липсва | `true` | Ученикът може да поиска AI анализ чрез Teacher108. Готов примерен отговор не е задължителен. |
| `true` | `true` | Достъпни са и предварително зададеният пример, и отделният AI анализ. |

`reference_answer` е **непразен текст до 20000 знака**, допустим само за `open_answer`. При включен `automatic_feedback` е задължителен; при AI режим самостоятелно може да липсва. Показва се като текст, без изпълнение на HTML. Не използвай `correct_option_ids` или `feedback` за свободен отговор — те са за задачите с избор.

При готовата обратна връзка ученикът първо въвежда отговор и натиска **„Предай отговора и виж пример“**. Предаденият отговор се запазва и заключва, а след това се показва примерът. Не се прави автоматична преценка „вярно/грешно“ чрез сравняване на текстовете. Състоянието на предаването се възстановява и след рестарт.

При `ai_feedback: true` Student108 изпраща към Teacher108 ученическия отговор, `mission_id` и `step_id`. Teacher108 добавя контекста на зададената мисия и изпраща заявка към настроения AI доставчик. Анализът обхваща качество, вярно, пропуснато, грешно, излишно/несвързано и примерен отличен отговор. AI обратната връзка при реална ученическа работа изисква ученически вход в Teacher108 и настроен AI доставчик. Прегледът без вход пропуска AI заявките и позволява преминаване напред със съобщение, че са изключени. От Student108 0.14.15 и Teacher108 0.13.9 `Student108.exe --preview` предлага и учителски вход: същият Student108 изпълнява пробни AI заявки през временна HTTPS сесия в Teacher108. Те се отчитат като преглед, отделно от ученическите изпълнения. Примерите от файл или URL се отварят след избора на режим. Ключовете за AI не присъстват в JSON мисията или шаблона. `allow_ai_hint` е отделно правило и не включва тази обратна връзка.

Пример за една стъпка с двата режима:

```json
{
  "id": "hardware-answer",
  "step_content": {
    "type": "open_answer",
    "title": "Хардуер",
    "instruction": "Какво е хардуер? Дай един пример.",
    "reference_answer": "Хардуерът включва физическите компоненти на компютъра, например клавиатурата."
  },
  "step_rules": {
    "automatic_feedback": true,
    "ai_feedback": true
  }
}
```

Пълен файл: [мисия с двата вида обратна връзка](../examples/missions/open-answer-feedback.json). При задачи с избор `automatic_feedback` показва верните `correct_option_ids` и незадължителното текстово обяснение `feedback` (до 20000 знака).

## Валидация и резултат

Приема се само `mission_version: 4`. Полетата `schema_version` и `revision` не се приемат в мисия. Старият плосък формат и смесените структури се отхвърлят. Например `instruction` трябва да бъде в `step_content`, а `time_limit_seconds` — в `step_rules`. На тези основни нива непознатите полета се отхвърлят. Размерът на зареждан от файл JSON на мисия е до 5 MB.

Подредбата на `steps` определя реда на работа. Подредбата на `options` може да бъде променена при показване, но ID остават същите. Правилото `do_not_shuffle_answers: true` запазва авторския ред.

Резултатът от мисия е отделен JSON документ. Той съдържа пълната мисия в `mission_snapshot`, идентификатор на резултата, ученик, отговори и състояние. `unanswered` е допустимо състояние, включително при завършена мисия. Форматът на резултата не се заменя с формата на мисията.

Готови файлове: [две мисии от един шаблон](../examples/README.md), [мисия с всички типове стъпки](../examples/missions/all-step-types.json), [мисия с време](../examples/missions/timed-mission.json).

### AI обратна връзка в JSON резултата

От Student108 **0.14.16** полученият анализ се запазва автоматично в `steps[].ai_feedback` в резултата, без отделен бутон „Обратна връзка“. „Напред“ заявява анализа. В прозореца се показват удебелени заглавия за шестте раздела, включително „Качество на отговора:“.

`ai_feedback` в резултата е обект, различен от булевото правило в `step_rules` на мисията:

| Поле | Значение |
|---|---|
| `request_id` | ID на заявката, получено от Teacher108. |
| `received_at` | Момент на получаване в UTC. |
| `answer` | Точният текст, за който е получен анализът. |
| `answer_sha256` | SHA-256 на UTF-8 текста на този отговор. |
| `result` | Текстовите полета `quality`, `correct`, `missing`, `incorrect`, `irrelevant`, `reference_answer`. |

Пази се последният получен анализ за стъпката. При рестарт се възстановява и се използва без нова AI заявка само ако отговорът съвпада. Ако ученикът редактира отговора, предишният анализ остава свързан с оригиналния `answer`, а новият текст изисква нов анализ. В реална ученическа работа тези данни се изпращат с JSON резултата към Teacher108; в режим преглед остават в локалния пробен резултат.

От Teacher108 **0.13.10** AI инструкцията включва сравнение за копиране от видимия учебен текст на предходните стъпки (`step_content.instruction` в наличния контекст). При съществено дословно копиране качеството трябва да бъде определено като лошо, дори фактите да са верни. Служебен HTML, стилове, скрито съдържание, следващи стъпки и непоказани примерни отговори не са основание за такъв извод.
