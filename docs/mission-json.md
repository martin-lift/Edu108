# JSON на мисия — схема 4

[Начало](../README.md) · [Шаблон](mission-template-json.md) · [Правила](rules.md)

Мисията е самостоятелно описание на конкретните стъпки, които ученикът получава. Съдържанието и правилата са отделени както за цялата мисия, така и за всяка стъпка.

## Минимален пример

```json
{
  "mission_version": 4,
  "mission_id": "hardware-one-question",
  "mission_content": {
    "title": "Хардуер",
    "steps": [
      {
        "id": "step-1",
        "step_content": {
          "type": "open_answer",
          "title": "Определение",
          "instruction": "Какво е хардуер?"
        },
        "step_rules": {}
      }
    ]
  },
  "mission_rules": {}
}
```

Празните обекти за правила са валидни и означават подразбиращите се стойности. Самите обекти `mission_content`, `mission_rules`, `step_content` и `step_rules` са задължителни.

## Основен обект

| Поле | Тип | Значение |
|---|---|---|
| `mission_version` | integer | Задължително `4`. Версия на JSON формата. |
| `mission_id` | string | Задължителен непразен идентификатор на конкретната мисия. |
| `mission_content` | object | Задължително съдържание на мисията. |
| `mission_rules` | object | Задължителни правила на мисията; може да е `{}`. |
| `student` | object | Незадължителни служебни данни, които Teacher108 добавя при получаване на мисия след вход. Не са част от авторските примери. |

**Мисията е непроменяема след генериране и няма `revision`.** Редактира се шаблонът и се генерира нова мисия с ново `mission_id`. Teacher108 отказва да презапише вече съхранена мисия със същото ID и различно описание. `mission_version` обозначава версията на JSON структурата, а не на учебното съдържание. `step_content_id` сочи избраното библиотечно съдържание. За шаблоните отделната версия на формата е `template_version`.

Различни мисии, съставени от един шаблон, получават различни `mission_id`. Повторна работа на ученик по една и съща мисия създава нов резултат от мисия, без да изисква ново `mission_id`.

## `mission_content`

| Поле | Тип | Значение |
|---|---|---|
| `title` | string | Задължително непразно заглавие. |
| `steps` | array | Задължителна последователност от 1 до 1000 стъпки. |
| `description` | string | Незадължително описание и цел; запазва се като метаданни, не е отделна начална страница в Student108. |
| `class_name`, `subject`, `category`, `lesson` | string | Незадължителни описателни полета. Могат да липсват или да са празни. |
| `persistent_text` | string | Незадължителен общ текст, показван над стъпките. |
| `content_format` | string | `"text"` по подразбиране или `"html"` за съдържанието на стъпките. |
| `mission_type` | string | `"millionaire"` включва „Стани богат“. При стандартните примери полето липсва. Виж [Типове мисии](mission-types.md). |

Описателните полета за клас, предмет и урок се пазят, но сами не филтрират ученици и не раздават мисията.

## Една конкретна стъпка

```json
{
  "id": "step-1",
  "step_content_id": 101,
  "step_content": {
    "type": "open_answer",
    "title": "Определение за хардуер",
    "instruction": "Какво е хардуер? Дай един пример.",
    "instruction_format": "text"
  },
  "step_rules": {
    "time_limit_seconds": 30,
    "allow_ai_hint": false
  }
}
```

| Поле | Тип | Значение |
|---|---|---|
| `id` | string | Задължително непразно ID, уникално в тази мисия. Свързва стъпката с ученическия отговор. |
| `step_content_id` | positive integer | Незадължително ID на избраното съдържание в учителската библиотека. |
| `step_content` | object | Задължително пълно копие на съдържанието. |
| `step_rules` | object | Задължителни окончателни правила за тази стъпка; може да е `{}`. |

`step_content_id` не замества съдържанието. Student108 трябва да може да работи само с получената мисия. Едно и също библиотечно съдържание може да присъства в различни мисии или стъпки; `id` на всяка стъпка в една мисия остава уникално.

## `step_content`

Общи задължителни полета: непразни `type`, `title`, `instruction`. Незадължително `instruction_format` заменя общия `content_format` за конкретната стъпка.

При избор на отговор се използва `options`, списък от обекти с непразни `id` и `text`. ID на отговорите са уникални в съответната стъпка. `correct_option_ids` винаги е **списък**, включително при един верен отговор. В готова стандартна мисия може да липсва; библиотеката на Wizard 1 изисква да се зададат верните отговори.

`lifeline_data` съдържа данни за жокерите, специфични за тази стъпка. Типовете и примери са описани в [Типове стъпки](step-types.md); жокерите — в [Правила](rules.md).

При HTML Student108 използва разрешен набор от тагове и атрибути. Импортираните скриптове не се изпълняват. HTML е начин за представяне на съдържание, а не начин за добавяне на програмна логика.

## Валидация и резултат

Приема се само `mission_version: 4`. Полетата `schema_version` и `revision` не се приемат в мисия. Старият плосък формат и смесените структури се отхвърлят. Например `instruction` трябва да бъде в `step_content`, а `time_limit_seconds` — в `step_rules`. На тези основни нива непознатите полета се отхвърлят. Размерът на зареждан от файл JSON на мисия е до 5 MB.

Подредбата на `steps` определя реда на работа. Подредбата на `options` може да бъде променена при показване, но ID остават същите. Правилото `do_not_shuffle_answers: true` запазва авторския ред.

Резултатът от мисия е отделен JSON документ. Той съдържа пълната мисия в `mission_snapshot`, идентификатор на резултата, ученик, отговори и състояние. `unanswered` е допустимо състояние, включително при завършена мисия. Форматът на резултата не се заменя с формата на мисията.
