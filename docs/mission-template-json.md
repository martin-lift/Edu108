# JSON стандарт за шаблон на мисия — версия 1

[Начало](../README.md) · [Процес](generation.md) · [Примери](../examples/README.md)

Това е стандартът за преносим JSON шаблон, приеман от Teacher108 чрез файл, поставен текст или `POST /template`. **`template_version: 1`** е версията на структурата, **`record_type: "mission_template"`** е видът на документа, а **`template_type`** е типът на шаблона. Ключовете са на английски; учебното съдържание може да е на български.

| `template_type` | Тип | Създаване и запис |
|---|---|---|
| `"standard"` | Стандартна | Wizard 1 задава типа автоматично, без избор от учителя. Импортът проверява стъпките и вариантите и ги записва в свързаните таблици. |
| `"millionaire"` | Стани богат | Импорт от файл, текст или POST. Проверява се общото описание; целият JSON се запазва в отделна таблица без преобразуване на игровите данни. |

`template_type` е задължително при импорт. Файл без него или с непознат тип се отказва. Примерните стандартни файлове са обновени с `"template_type": "standard"`. Съществуващите стандартни записи в базата получават този тип автоматично. Типът не е версия на формата.

Версията на шаблона е независима от **`mission_version: 4`** за конкретните мисии. Поле `revision` не се използва. Редактираме шаблона; генерираме нови конкретни мисии с нови `mission_id`. Структури със старото общо `schema_version` не се приемат като шаблони или мисии.

Машинно описание: [JSON Schema — mission-template-v1.schema.json](../schemas/mission-template-v1.schema.json), Draft 2020-12. Освен структурните ограничения Teacher108 проверява връзките между ID и останалите условия, описани по-долу.

## Минимален самостоятелен стандартен шаблон

```json
{
  "template_version": 1,
  "template_type": "standard",
  "record_type": "mission_template",
  "title": "Хардуер",
  "description": "Ученикът обяснява какво е хардуер и дава пример.",
  "mission_rules": {},
  "steps": [
    {
      "title": "Определение за хардуер",
      "step_rules": {"time_limit_seconds": 30},
      "variants": [101]
    }
  ],
  "step_contents": [
    {
      "id": 101,
      "step_content": {
        "type": "open_answer",
        "title": "Определение за хардуер",
        "instruction": "Какво е хардуер? Дай един пример."
      }
    }
  ]
}
```

Пълният [шаблон „Хардуер и софтуер“](../examples/templates/hardware-software.json) включва пет съдържания за хардуер и шест за софтуер в същия файл. Отделната примерна библиотека не е необходима за импорта му.

## Основен обект

| Поле | Тип | Изискване и значение |
|---|---|---|
| `template_version` | integer | Задължително `1`. Версия на JSON структурата на шаблона. |
| `template_type` | string | Задължително `"standard"` или `"millionaire"`. Определя проверките и начина на запис. |
| `record_type` | string | Задължително `"mission_template"`. |
| `title` | string | Задължително непразно име, до 300 знака. |
| `description` | string | Задължително описание и цел в свободен текст, до 20 000 знака. |
| `class_name` | string | Незадължителен клас, до 300 знака. |
| `subject` | string | Незадължителен предмет, до 300 знака. |
| `category` | string | Незадължителна категория, до 300 знака. |
| `lesson` | string | Незадължителен урок, до 300 знака. |
| `mission_rules` | object | Задължителен при `standard`; може да е `{}`. При `millionaire` е незадължителен обект. |
| `steps` | array | При `standard`: задължителни 1–1000 стъпки. При `millionaire`: незадължителен списък, запазван без преобразуване. |
| `step_contents` | array | При `standard`: задължителни 1–10000 определения на съдържание. При `millionaire`: незадължителен списък вътре в целия JSON. |

Незадължителните описателни полета могат да липсват или да са `""`. `null` не е празен текст. Класът, предметът, категорията и урокът не са ограничения за достъп и не раздават автоматично мисията.

`mission_content` от конкретната мисия не се добавя на горно ниво в шаблона. Описателните данни на шаблона са полетата в тази таблица.

## Стъпка в стандартния шаблон

| Поле | Тип | Значение |
|---|---|---|
| `title` | string | Задължително име/тема на позицията, до 300 знака. |
| `step_rules` | object | Задължителни правила по подразбиране за вариантите в тази позиция; `{}` е допустимо. |
| `variants` | array of integer | Непразен списък с различни положителни ID от `step_contents`, до 10000 варианта. |

Редът на `steps` определя реда на бъдещата мисия. От `variants` се избира точно един вариант за конкретната мисия. Един и същ ID може да се използва в различни стъпки, но не се повтаря в списъка на една стъпка.

Вариантите са **цели съдържания на стъпка**. Те са различни от `options`, които са отговорите за избор вътре в един въпрос. Един вариант може да е свободен отговор, друг — избор на отговор. Избраният вариант определя типа на конкретната стъпка.

Шаблонът няма отделно JSON `id` на позициите си. Базата пази вътрешни ID и позиции; генерираната мисия получава свои уникални ID на стъпките.

## Съдържания в стандартния шаблон — `step_contents`

Всеки елемент има точно `id` и `step_content`:

```json
{
  "id": 101,
  "step_content": {
    "type": "open_answer",
    "title": "Определение за хардуер",
    "instruction": "Какво е хардуер? Дай един пример.",
    "instruction_format": "text"
  }
}
```

`id` е положително цяло число, уникално **вътре във файла**. То не сочи към съществуващ запис на компютъра на получателя. `step_content` включва общите `type`, `title`, `instruction` и незадължителен `instruction_format`. При избор на отговор включва `options` и задължителен `correct_option_ids`. Ограниченията са в [Типове стъпки](step-types.md).

Стандартният шаблон включва типовете съдържание и правилата, които Wizard 1 може да редактира. В този тип `lifeline_data`, `allowed_lifelines` и игровите правила не се приемат. Неподдържано поле се отхвърля с обяснение. В JSON шаблон `millionaire` такива игрови данни могат да се пазят като част от целия документ, без да се преобразуват или премахват.

Задължителни проверки на връзките:

- Всяко ID във `variants` има точно едно описание в `step_contents`.
- В `step_contents` няма две определения с едно и също ID.
- Всяко включено съдържание участва поне в една стъпка; ненужните записи се премахват от файла.
- ID на отговорите в един въпрос са уникални, включително след премахване на крайни интервали.
- Всеки `correct_option_ids` сочи реален отговор от `options` и няма повторения.

[Отделната примерна библиотека](../examples/step-content-library.json) остава справочен каталог. За импорт използвай самостоятелните файлове в `examples/templates/`.

## Обратна връзка за свободен отговор

От **Teacher108 0.13.8** и **Student108 0.14.14** стандартният шаблон поддържа два независими режима:

- `steps[i].step_rules.automatic_feedback: true` показва предварително зададен пример след предаване и заключване на ученическия отговор. В **всеки вариант** на тази позиция със свободен отговор трябва да има `step_content.reference_answer` — непразен текст до 20000 знака.
- `steps[i].step_rules.ai_feedback: true` разрешава AI анализа през Teacher108. **Всички варианти** на тази позиция трябва да са `open_answer`. `reference_answer` не е задължителен, ако готовата обратна връзка е изключена.

Двата параметъра са `false` по подразбиране; могат да се включат заедно или поотделно. Не ги поставяй в `step_content`. Примерният отговор е съдържание, затова е в `step_contents[i].step_content.reference_answer`, а не в `step_rules`. В Wizard 1 се попълва в „Съдържание на стъпката“ → „Примерен отговор“; режимите се включват в правилата на стъпката.

При `automatic_feedback` варианти с избор също са допустими и използват `correct_option_ids` и незадължителното обяснение `feedback`. Информационни стъпки, предаване на файл и избор на мисия не поддържат този режим. При `ai_feedback` смесване с варианти от друг тип се отказва. Готовият пример не оценява автоматично свободния текст; AI анализът е отделна заявка с вход в Teacher108 и настроен AI доставчик.

Пълен самостоятелен файл за импорт: [шаблон с режимите за обратна връзка](../examples/templates/open-answer-feedback.json). При генериране Teacher108 копира избрания `reference_answer` в съдържанието на конкретната мисия, а двата параметъра — в окончателните `step_rules`. JSON схемата проверява структурата и типовете; връзките между `variants`, типа на съдържанието и задължителния примерен отговор се проверяват от валидатора на Teacher108 при импорт. Форматите остават `template_version: 1` и `mission_version: 4`. Подробна таблица с четирите комбинации: [JSON на мисия](mission-json.md#обратна-връзка-за-свободен-отговор).

## JSON шаблон „Стани богат“

За `template_type: "millionaire"` са задължителни общите `template_version`, `template_type`, `record_type`, `title` и `description`. Клас, предмет, категория и урок имат същите ограничения като при стандартния тип. Ако присъстват, `mission_rules` трябва да е обект, а `steps` и `step_contents` — списъци.

Допълнителните игрови полета и вложени данни се запазват, включително полета без редактор. Не се проверяват игровата стълбица, жокерите, въпросите, вариантите и връзките между тях. Може да се пази и непълна чернова. **Успешният импорт потвърждава валидно общо описание и съхранен JSON; не означава готовност за генериране или работа в Student108.**

Минимална чернова за съхранение:

```json
{
  "template_version": 1,
  "template_type": "millionaire",
  "record_type": "mission_template",
  "title": "Стани богат — хардуер",
  "description": "Ученикът разпознава устройствата на компютъра.",
  "mission_rules": {"game": {"ladder": [100, 200], "safe_levels": [1], "unit": "точки"}},
  "steps": [],
  "step_contents": []
}
```

[Пример с въпроси, игрови правила и жокери](../examples/templates/stani-bogat.json). Вътрешната организация в примера още не е договорен стандарт за генериране от шаблон.

Записът е в **`mission_template_documents`** в базата `mission_templates.sqlite3`. Таблицата има служебни `id`, `teacher_id`, `created_at`, `updated_at` и поле **`document` с целия JSON текст**. Съдържанието и форматирането се запазват; UTF-8 BOM не е част от JSON текста. Не се добавят записи в `mission_templates`, `template_steps`, `template_variants` или `step_content`. ID вътре в документа не се преномерират и не стават ID на общата библиотека.

Типът и ID заедно определят записа: числовото ID на JSON документ може да съвпада с ID на стандартен шаблон в другата таблица. Преглед: **Мисии → „Шаблони на мисии“ → „Стани богат“** — само документите на вписания учител, с възможност за копиране. Те не се отварят за редакция в Wizard 1. Повторен импорт създава нов документ.

## Импорт в Teacher108

1. В лявото меню отвори **„Мисии“ → „Import JSON…“**.
2. Натисни **„Прочети от файл…“** или постави целия JSON в текстовото поле.
3. Натисни **„Провери JSON“**. Четенето от файл стартира проверката автоматично.
4. Прегледай разпознатия тип и начина на запис. За стандартен шаблон се показват стъпките, вариантите и новите съдържания. За „Стани богат“ се пояснява, че се записва целият JSON и игровата готовност не е проверена.
5. Натисни **„Добави шаблона“**. Стандартният шаблон се отваря в Wizard 1. JSON шаблонът „Стани богат“ се записва отделно и не замества отворения стандартен шаблон.

Проверката не променя базата. Редакция на текста отменя предходната проверка; преди добавяне се проверява отново. При отваряне на импортиран стандартен шаблон незаписаната работа е защитена с избор за запазване, отхвърляне или отказ. Импортът на „Стани богат“ я оставя непокътната.

При импорт на **стандартен** шаблон всеки включен запис получава **ново местно ID**. Всички връзки към него се пренасочват към същото ново ID. Съдържание, споделено от няколко стъпки в JSON, остава споделено и в базата. Няма автоматично свързване с местни или чужди учителски записи по съвпадение на ID.

Шаблонът, съдържанията и връзките се записват в една транзакция. При неуспех не остават частични записи. Съществуващи шаблони и съдържания не се презаписват. Повторен импорт създава отделно копие.

Служебните `id`, `teacher_id`, `updated_at` на шаблона се определят от базата. Те не са полета на преносимия JSON. `TemplateStore.load` връща вътрешен модел; това не е директно готов преносим файл. Файловият **експорт** от уизърда още предстои.

## Импорт с POST към учителския сървър

Екранът „Import JSON…“ показва **„или изпрати с POST към URL:“**, точния адрес за копиране и дали сървърът работи. Адресът е `http://<учителски-компютър>:<порт>/template?pin=123456`; числото е примерен пин. Портът по подразбиране е **8108**, но се използва текущият порт от Teacher108.

В Teacher108 трябва да има вписан учител и HTTP сървърът да е стартиран от „Текуща мисия“. Шаблонът се записва в библиотеката на този учител. Заявката не приема `teacher_id` за избор на акаунт.

При отваряне на формата URL се попълва със записания валиден шестцифрен пин на учителя. Ако липсва или е изтекъл, се генерира и записва нов. Пинът може да започва с нула — използвай всичките шест цифри. Бутонът **„Генерирай нов пин“** заменя текущия код и обновява URL, без да променя въведения JSON.

Пинът се пази в настройките **отделно за всеки учител** и е валиден **24 часа от генерирането или до генериране на нов**. Използва се за повече от една заявка. Отварянето на формата и успешните POST заявки не удължават срока. Рестартът и изходът от акаунта не го изтриват; след повторен вход той работи до първоначалното си изтичане. Екранът показва крайния срок. Ако изтече, докато формата е отворена, натисни „Генерирай нов пин“ или отвори формата отново.

Параметърът **`pin` е задължителен** и трябва да се среща точно веднъж в URL. Сървърът проверява кода за текущо вписания учител преди обработка на JSON и повторно преди запис. Генериране на нов пин или изтичане по време на обработката отменя импорта. Пинът е разрешение за HTTP импорта; не е поле на JSON шаблона. Импортът от файл и поставен текст не изисква пин.

Изпрати **целия JSON шаблон като тяло**, с `Content-Type: application/json` и UTF-8 кодировка. Не използвай multipart, поле `file` или допълнителен външен обект. Например от PowerShell на учителския компютър, от папката Edu108:

```powershell
curl.exe -X POST "http://localhost:8108/template?pin=123456" -H "Content-Type: application/json" --data-binary "@examples/templates/hardware-software.json"
```

Замени `123456` с пина от формата. За изпращане от друг компютър замени `localhost` с името или IP адреса на учителския компютър и използвай неговия порт. Адресът в екрана е готов за копиране заедно с пина.

При успех сървърът връща **HTTP 201 Created**:

```json
{
  "status": "imported",
  "template_id": 12,
  "template_type": "standard",
  "storage": "structured",
  "title": "Хардуер и софтуер",
  "steps_count": 2,
  "contents_count": 11
}
```

`template_id` е новото местно ID; числото в примера е илюстративно. `template_type` и `storage` определят вида на записа. При `millionaire` отговорът има `storage: "json_document"`, `steps_count: null` и `contents_count: 0`, защото не са създадени отделни стъпки или библиотечни съдържания. След отговора записът вече е завършен. Стандартните шаблони се виждат в Wizard 1, а JSON документите — чрез Мисии → „Шаблони на мисии“ → „Стани богат“. Текущият отворен шаблон и незаписаните му промени се запазват. Повторен POST създава ново копие.

| HTTP код | Значение |
|---|---|
| `201` | Стандартният шаблон и връзките му или целият JSON документ са записани успешно. |
| `403` | Липсващ, грешен, изтекъл, заменен или чужд пин; повторен параметър `pin`. |
| `422` | Невалиден JSON, UTF-8 текст или описание на шаблон. |
| `413` | Тялото е по-голямо от 5 MB. |
| `415` | Липсва или е неправилен `Content-Type: application/json`. |
| `503` | Няма вписан учител за приемане на шаблона. |
| `409` | Учителят е излязъл или е сменен, докато заявката се обработва; шаблонът не е добавен. |
| `500` | Записът не е успял; няма частичен импорт. |

Всеки отказ има обяснение на български в `detail`. При грешка във валидацията има и `errors` — списък от отделните съобщения с JSON път или ред и колона. Използват се същите проверки като при файл и поставен текст. Изходът от акаунта спира HTTP импорта на шаблони, дори сървърът да продължава да обслужва Student108.

При **всяка грешка от `POST /template`** отговорът се изпраща след допълнително **изчакване от 5 секунди**, включително при грешен пин, невалиден JSON и неуспешен запис. Изчакването не блокира обработката на други заявки към сървъра. Успешният отговор `201` няма това забавяне.

## Валидация и съобщения

Използва се UTF-8, включително UTF-8 с BOM. Максималният размер е 5 MB. В JSON няма коментари или Markdown огради. И при двата типа се отхвърлят повтарящи се имена на полета, невалиден Unicode, безкрайни числа, `NaN`, `Infinity`, неподдържана версия или тип и невалидно общо описание. При `standard` се отхвърлят и непознати полета и невалидни структури на стъпки и правила. При `millionaire` допълнителните игрови полета се запазват; служебни полета като `teacher_id`, `id`, `revision`, `schema_version` и полета на конкретна мисия не са допустими на горно ниво.

Синтактичните грешки посочват **ред и колона**, обяснение и откъс с указател. Грешките в данните посочват JSON път и човешки номер, например:

```text
$.steps[1] (стъпка 2).variants[0] (вариант 1): Липсва описание за съдържание 201.
Добави го в step_contents или поправи ID. ID от местната база не се използват автоматично.
```

JSON индексите започват от 0, а човешките номера на стъпките и вариантите — от 1. Показват се няколко грешки едновременно, до първите 100, за да могат да бъдат поправени заедно. Текстът остава в полето за редакция.

За стойностите по подразбиране и заместването на правила виж [Rules](rules.md). За избраните стъпки в готовия документ виж [JSON на мисия](mission-json.md).
