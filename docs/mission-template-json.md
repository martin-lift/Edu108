# JSON на шаблон на мисия

[Начало](../README.md) · [Процес](generation.md) · [Примери](../examples/README.md)

Шаблонът описва какви мисии могат да се съставят. За всяка стъпка има списък от възможни варианти и общи за тях правила.

## Статус на формата

Описанието по-долу следва обекта, който текущият `TemplateStore.save` в Teacher108 приема за запис. Уизърдът съхранява тези данни в отделната база `mission_templates.sqlite3`. Това **още не е внедрен формат за файлов импорт/експорт** и няма собствено утвърдено `schema_version` за шаблон.

Примерните файлове са данни за подготовка на шаблон. Те не са мисии със схема 4 и не се отварят в Student108. Полетата `mission_content` и `step_content` от конкретната мисия не се пренасят механично на горно ниво в шаблона.

## Основен обект

```json
{
  "title": "Хардуер и софтуер",
  "description": "Разпознаване на хардуер и софтуер чрез два въпроса.",
  "class_name": "8. клас",
  "subject": "Информационни технологии",
  "category": "Компютърни системи",
  "lesson": "Хардуер и софтуер",
  "mission_rules": {
    "allow_back_navigation": true,
    "show_progress_panel": true
  },
  "steps": [
    {
      "title": "Хардуер",
      "step_rules": {
        "time_limit_seconds": 30,
        "allow_ai_hint": false,
        "send_progress": false,
        "do_not_shuffle_answers": false
      },
      "variants": [101, 102, 103, 104, 105]
    },
    {
      "title": "Софтуер",
      "step_rules": {
        "time_limit_seconds": 30,
        "allow_ai_hint": false,
        "send_progress": false,
        "do_not_shuffle_answers": false
      },
      "variants": [201, 202, 203, 204, 205, 206]
    }
  ]
}
```

Пълният файл: [hardware-software.json](../examples/templates/hardware-software.json).

| Поле | Тип | Изискване и значение |
|---|---|---|
| `title` | string | Задължително непразно име, до 300 знака. |
| `description` | string | Задължително описание и цел в свободен текст, до 20 000 знака. |
| `class_name` | string | Незадължителен клас, до 300 знака. |
| `subject` | string | Незадължителен предмет, до 300 знака. |
| `category` | string | Незадължителна категория, до 300 знака. |
| `lesson` | string | Незадължителен урок, до 300 знака. |
| `mission_rules` | object | Правила по подразбиране на мисията. Липсващи стойности се допълват. |
| `steps` | array | От 1 до 1000 стъпки в определения ред. |

Незадължителните описателни полета могат да липсват или да са `""`. Те не са ограничения за достъп и не определят автоматично на кои ученици ще бъде раздадена мисията.

## Стъпка в шаблона

| Поле | Тип | Значение |
|---|---|---|
| `title` | string | Задължително име/тема на позицията, до 300 знака. Например „Хардуер“. |
| `step_rules` | object | Общи правила по подразбиране за всички варианти в тази позиция. |
| `variants` | array of integer | Непразен списък с различни ID на активни записи от библиотеката. |

Редът на елементите в `steps` определя реда на мисията. Редът в `variants` е списък от възможности; всички варианти не се изпращат като последователни задачи. За конкретната мисия се избира един.

Вариантите са цели съдържания на стъпка. Те са различни от `options`, които са отговорите за избор вътре в един въпрос. Един вариант може да е свободен отговор, друг — избор на отговор. Избраният вариант определя типа на конкретната стъпка.

В текущия шаблон няма отделно `id` на всяка стъпка в JSON обекта. Базата пази вътрешни ID и позиции; конкретната мисия получава свои уникални ID на стъпките.

## Връзка към библиотеката

В примерите ID 101 обозначава:

```json
{
  "id": 101,
  "step_content": {
    "type": "open_answer",
    "title": "Определение за хардуер",
    "instruction": "Какво е хардуер? Дай един пример.",
    "instruction_format": "text"
  }
}
```

[step-content-library.json](../examples/step-content-library.json) е **помощен документ за примерите**: списък с `id` и `step_content`. Тази външна обвивка не е внедрен API за импорт и не е пълният SQL запис. В реалната база съдържанието се пази като JSON в `step_content.document`, заедно със собственик, активно състояние, връзка към заменен запис и времеви полета.

Примерните ID са локални за тази примерна библиотека. При запис чрез `save_content` Teacher108 създава реалните ID; връзките в шаблона трябва да се пренасочат към тях. Не трябва да се приема, че ID 101 от два различни компютъра означава едно и също съдържание.

## Запис и редакция

`TemplateStore.load` връща и служебните `id`, `teacher_id`, `updated_at` на шаблона. Те не се попълват в примерните файлове: базата ги определя. При обновяване ID на шаблона се подава отделно на операцията за запис.

Новите записи в библиотеката се пазят веднага. Премахването на вариант от шаблона не изтрива съдържанието. Неактивен или чужд запис не може да бъде записан като използваем вариант в шаблона.

Правописна корекция запазва ID. Промяна на смисъла създава нов ID и деактивира стария. Шаблоните, които сочат стария запис, трябва да изберат активен заместител преди нов запис. Вече съставените мисии запазват своите копия.

За текущите допустими правила виж [Rules](rules.md). За избраните стъпки в готовия документ виж [JSON на мисия](mission-json.md).
