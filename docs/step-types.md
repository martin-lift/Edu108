# Типове стъпки

[Начало](../README.md) · [JSON на мисия](mission-json.md) · [Правила](rules.md)

Типът е в `step_content.type`. Всички типове имат задължителни непразни `title` и `instruction`. В конкретната мисия съдържанието се обвива с `id`, незадължително `step_content_id` и `step_rules`.

| Български | English | JSON стойност | Какво предава ученикът |
|---|---|---|---|
| Информационна стъпка | Information step | `information` | Не се изисква отговор. |
| Свободен отговор | Open answer | `open_answer` | Текст. |
| Избор на един отговор | Single choice | `single_choice` | Списък с един избран ID или празен списък. |
| Избор на няколко отговора | Multiple choice | `multiple_choice` | Списък с избрани ID или празен списък. |
| Предаване на файл | File submission | `file` | Един приложен файл или липса на файл. |

В Wizard 1 изборите са означени „Един верен отговор“ и „Няколко верни отговора“. Те съответстват на `single_choice` и `multiple_choice`.

## Информационна стъпка — `information`

```json
{
  "type": "information",
  "title": "Въведение",
  "instruction": "Хардуерът са физическите части на компютъра, а софтуерът — програмите."
}
```

Показва учебен текст или указания. Няма поле за предаване на отговор. Посетена информационна стъпка се отбелязва като `read`. При преминаване напред не се изисква потвърждение за липсващ отговор. Може да има време за прочитане чрез `step_rules`.

## Свободен отговор — `open_answer`

```json
{
  "type": "open_answer",
  "title": "Хардуер",
  "instruction": "Какво е хардуер? Дай един пример."
}
```

Ученикът въвежда свободен текст. Празен текст или текст само от интервали не се брои като отговор. Този тип няма `options` или `correct_option_ids`.

## Избор на един отговор — `single_choice`

```json
{
  "type": "single_choice",
  "title": "Разпознай хардуера",
  "instruction": "Кое от изброените е хардуер?",
  "options": [
    {"id": "keyboard", "text": "Клавиатура"},
    {"id": "browser", "text": "Уеб браузър"},
    {"id": "os", "text": "Операционна система"}
  ],
  "correct_option_ids": ["keyboard"]
}
```

Избира се най-много един отговор. Когато е зададен `correct_option_ids`, той съдържа точно един ID. Името на полето остава в множествено число, защото стойността е списък.

В „Стани богат“ този тип е задължителен за всички стъпки и всяка трябва да има точно четири варианта и един зададен верен отговор.

## Избор на няколко отговора — `multiple_choice`

```json
{
  "type": "multiple_choice",
  "title": "Входни устройства",
  "instruction": "Отбележи входните устройства.",
  "options": [
    {"id": "keyboard", "text": "Клавиатура"},
    {"id": "mouse", "text": "Мишка"},
    {"id": "monitor", "text": "Монитор"}
  ],
  "correct_option_ids": ["keyboard", "mouse"]
}
```

Ученикът може да избере повече от един отговор. При зададен списък с верните отговори той е непразен, няма повторения и съдържа само ID от `options`.

При двата типа за избор готовата мисия изисква поне два варианта. Библиотеката на Wizard 1 допуска от 2 до 30 и изисква отбелязване на верните отговори. В стандартен JSON на мисия `correct_option_ids` може да липсва; това не е допустимо за „Стани богат“ и за жокер, който премахва грешни варианти.

Редът на показване по подразбиране се размесва. При необходимост се задава `step_rules.do_not_shuffle_answers: true`. Резултатът пази избраните ID, не показаните букви.

## Предаване на файл — `file`

```json
{
  "type": "file",
  "title": "Кратък документ",
  "instruction": "Създай документ с два примера за хардуер и два за софтуер. Приложи файла."
}
```

Позволява прилагане на един файл до 20 MB. Резултатът съдържа името, размера, SHA-256 и съдържанието в Base64. Прикачването на нов файл заменя текущия отговор на тази стъпка. Приложението не изпълнява прикачения файл.

При липса на файл стъпката остава `unanswered`. Ако има времеви лимит, файл трябва да бъде приложен преди изтичането му.

## Общи допълнения

`instruction_format` може да е `text` или `html`. Ако липсва, се използва `mission_content.content_format`, а ако и той липсва — `text`. `lifeline_data` може да съдържа данни за достъпните жокери.

Правилата за време, подсказки, навигация и междинно изпращане не са част от самия тип или условието. Поставят се в [Rules](rules.md).
